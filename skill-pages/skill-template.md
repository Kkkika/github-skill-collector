# Skill 名称

提供一个清晰、简洁的描述，说明该技能涵盖的内容以及何时使用它。此描述出现在技能发现中，应帮助代理（和人类）确定何时该技能是相关的。

**重要**：为了获得最佳性能，请将 SKILL.md 主体保持在 500 行以内。将详细的参考资料移动到 `references/` 目录下的单独文件中。

## 何时激活

描述应激活此技能的具体情况、任务或上下文。包括直接触发器（特定关键字或任务类型）和间接信号（表明技能相关性的更广泛模式）。

用第三人称书写。该描述被注入到系统提示中，不一致的视角会导致发现问题。

- 好的例子：“处理 Excel 文件并生成报告”
- 避免：“我可以帮你处理 Excel 文件”

## 核心概念

解释此技能涵盖的基本概念。这些是技能教授的心智模型、原则或框架。

默认假设：Claude 已经非常聪明了。只添加 Claude 尚未拥有的上下文。挑战每一条信息：
- “Claude 真的需要这个解释吗？”
- “我可以假设 Claude 知道这个吗？”
- “这段话是否证明了它的令牌成本是合理的？”

## 详细主题

### 主题 1

提供第一个主要主题的详细解释。包括具体技术、模式或方法。使用示例来说明概念。

### 主题 2

提供第二个主要主题的详细解释。根据需要继续添加其他主题。

对于较长的主题，考虑将内容移动到 `references/` 并链接：
- 参见 [详细参考](./references/topic-details.md) 了解完整实现

## 实践指南

提供应用该技能的可操作指南。包括常见模式、要避免的反模式以及在不同方法之间进行选择的决策框架。

将特异性水平与任务的脆弱性相匹配：
- **高自由度**：多种方法均有效，决定取决于上下文
- **中等自由度**：存在首选模式，可以接受一些变化
- **低自由度**：操作脆弱，必须遵循特定顺序

## 示例

提供具体的示例来说明技能的应用。示例应显示之前/之后的比较，演示正确用法，或显示如何处理边缘情况。

使用输入/输出对以清晰起见：

**示例：**
```
Input: [describe input]
Output: [show expected output]
```

## 准则

列出应用此技能时要遵循的具体准则。这些应该是可以检查或验证的可操作规则。

1. 具有具体、可验证标准的准则一
2. 具有明确成功条件的准则二
3. 根据需要继续

## 集成

解释此技能如何与集合中的其他技能集成。以纯文本形式列出相关技能（不是链接），以避免跨目录引用问题：

- skill-name-one - 关系的简要描述
- skill-name-two - 关系的简要描述
